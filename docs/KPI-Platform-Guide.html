3. How to deploy a change (the normal way)

Everything is automated through the Azure DevOps pipeline and a self-hosted agent (KPI-VPS, pool calm) that runs on the VPS itself:

  1. Edit code locally (repo: D:\kpi-platform on the work laptop)
  2. git add .
     git commit -m "describe the change"
     git push azure main        (and optionally: git push origin main)
  3. Done. The pipeline builds the frontend, installs backend deps,
     syncs the database schema (prisma db push), copies files into
     C:\apps\kpi-platform, restarts the backend and health-checks it.

Watch progress: Azure DevOps → Pipelines → latest run (~6–8 minutes). Green = deployed and verified.

No server access is needed for code changes. RDP to the VPS is only required for infrastructure work: new secrets in .env, certificates for new domains, IIS changes.

5. Email

Sender: kpi@calmglobal.com via MailerSend SMTP (smtp.mailersend.net:587, calmglobal.com domain verified — same account as the RealCousins project). Emails sent: welcome on registration, staff invites, password reset, password-changed confirmation, and KPI alert notifications from the sync module.

Settings live only in C:\apps\kpi-platform\backend\.env (SMTP_*, EMAIL_FROM). After changing them: C:\Windows\System32\inetsrv\appcmd.exe recycle apppool /apppool.name:kpi-api

7. Runbook — common operations (on the VPS, admin PowerShell)

Restart the backend

C:\Windows\System32\inetsrv\appcmd.exe recycle apppool /apppool.name:kpi-api

View recent backend logs

$f = Get-ChildItem C:\apps\kpi-platform\backend\logs\node*.log | Sort-Object LastWriteTime -Descending | Select-Object -First 1; Get-Content $f.FullName -Tail 60

Force a database schema sync (after pulling schema changes manually)

cd C:\apps\kpi-platform\backend; npx prisma db push

9. Security notes

Rotate when convenient (values were exchanged in chat during setup): the PostgreSQL passwords (both the postgres and dossiro users) and the MailerSend SMTP password. After rotating, update backend\.env here (and RealCousins' .env for SMTP) and recycle the app pools.
  • JWT secrets are random, generated at setup, stored only in backend\.env.
  • Staff invites use fixed temp password Welcome@123 — consider changing to random per-invite.
  • Public registration is open (see §4). Decide: restrict, or keep open for multi-tenant use.
  • The Brevo fallback in mailer.js has a hardcoded personal Gmail default sender — harmless while Brevo is unused, but worth cleaning up.
