# Deploying the KPI Platform to the CalmGlobal IIS server

Target architecture — everything on the OVH Windows VPS (`158.69.198.49`, IIS 10):

| Piece | Where | URL |
|---|---|---|
| Backend (Express + Prisma) | IIS site **KPI-API** → Node via HttpPlatformHandler | `https://kpi-api.calmglobal.com` |
| Frontend (React/Vite build) | IIS site **KPI-Web** → static `dist/` | `https://kpi.calmglobal.com` |
| Database | PostgreSQL already installed on the VPS | `localhost:5432/kpi_platform` |

## Step 1 — DNS (GoDaddy)

In the GoDaddy DNS manager for **calmglobal.com**, add two **A records**
(this does not touch the existing website, which lives on a different server):

| Type | Name | Value | TTL |
|---|---|---|---|
| A | `kpi-api` | `158.69.198.49` | 1 Hour |
| A | `kpi` | `158.69.198.49` | 1 Hour |

Verify from any machine: `nslookup kpi-api.calmglobal.com` → should return `158.69.198.49`.

## Step 2 — Server setup (RDP into 158.69.198.49)

1. RDP into the server, open **PowerShell as Administrator**.
2. Download just the setup script (the script clones the full repo itself):

   ```powershell
   mkdir C:\apps -Force; cd C:\apps
   Invoke-WebRequest https://raw.githubusercontent.com/iamlekside2/kpi-platform/main/deploy/setup-server.ps1 -OutFile setup-server.ps1
   powershell -ExecutionPolicy Bypass -File setup-server.ps1
   ```

3. The script will prompt once for the **local postgres password** (used to build
   `DATABASE_URL` in `backend\.env`). Everything else is automatic:
   Node LTS, Git, URL Rewrite, HttpPlatformHandler, repo clone, `npm ci`,
   database creation, Prisma migrations, frontend build, IIS app pools + sites.

## Step 3 — HTTPS (after DNS resolves)

```powershell
cd C:\apps\kpi-platform\deploy
powershell -ExecutionPolicy Bypass -File get-ssl.ps1
```

Uses win-acme (Let's Encrypt, free) — issues one cert for both hostnames,
adds the HTTPS bindings, and registers auto-renewal.

HTTPS is **required** for login to work: the refresh-token cookie is
`Secure; SameSite=None` in production, so browsers only send it over HTTPS.

## Step 4 — Smoke test

- `https://kpi-api.calmglobal.com/api/health` → `{"status":"ok", ...}`
- `https://kpi.calmglobal.com` → login page; register an account; log in.

## Redeploying after code changes

Push to GitHub, then on the server:

```powershell
powershell -ExecutionPolicy Bypass -File C:\apps\kpi-platform\deploy\deploy-update.ps1
```

## Files in this folder

| File | Purpose |
|---|---|
| `setup-server.ps1` | One-time server setup (run as admin on the VPS) |
| `get-ssl.ps1` | Issue/renew Let's Encrypt cert + HTTPS bindings |
| `deploy-update.ps1` | Pull + rebuild + restart after new commits |
| `backend.web.config` | IIS → Node (HttpPlatformHandler) config, copied to `backend/` |
| `frontend.web.config` | SPA fallback rewrite, copied to `frontend/dist/` |
| `backend.env.example` | Production env template → `backend\.env` |

## Notes / gotchas

- The backend app pool is `AlwaysRunning` with no idle timeout so the
  integration sync scheduler keeps running; don't change that.
- `backend\.env` lives only on the server (gitignored). JWT secrets are
  auto-generated by the setup script.
- Email (password reset, notifications) is optional — fill the
  `RESEND_*`/`BREVO_*`/`SMTP_*` vars in `backend\.env` when ready and run
  `Restart-WebAppPool kpi-api`.
- Logs: `C:\apps\kpi-platform\backend\logs\node*.log` (Node stdout) and the
  usual IIS logs in `C:\inetpub\logs\LogFiles`.
